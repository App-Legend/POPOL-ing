# 건우 작업 기록

## 2026-11-12

**완료**
- 하네스 마무리(`app/` 기능별 `register()` 조립 구조, 두 OS CI, PR 템플릿, `main` push 차단 훅) 및 macOS 프로세스 실행·로그·트리 종료 검증
- **결정:** macOS는 새 프로세스 그룹(`perl -e 'setpgrp(0,0); exec @ARGV'`)으로 실행하고, 종료는 그룹 전체에 TERM → 몇 초 뒤 KILL. 일반 `Process.kill()`은 손자 프로세스가 남고, Dart `detachedWithStdio`는 pgid≠pid라 종료 대상을 알 수 없다.
- **결정:** A 계약(`Orchestrator`·`RuntimeQuery`·`core/events`)은 1.0 태그 뒤 추가로 올린다. 1.0 뒤에도 새 계약 추가는 허용된다.
- **결정:** `AGENTS.md`는 만들지 않는다. 팀원 모두 Claude Code만 써서 `CLAUDE.md`로 충분하다.
- 기획 v0.9: AI 프로젝트 검사를 Gemini API로 MVP에 포함(AI-02·03, D 담당)하고 역할분담·일정·CLAUDE.md 반영, `core/`에 AI용 계약(`LlmClient`·`LogExcerpt`·`EnvDiff`) 추가
- **결정:** MVP AI는 로컬 LLM 대신 Gemini API로 한다. 6주 안에 AI를 넣기 위해 설치·모델 부담이 없는 쪽을 택함
- 기획서 v1.0 정리(문서 간 충돌 해소, 정해진 남은 결정 이동) 및 역할 재배분·3·4주차 전반/후반 일정 분할
- **결정:** 기본 QA(FR-10, 화면 6, `qa/`)는 C가 맡고 나머지는 D가 그대로 맡는다. QA는 C의 `HttpProbe`·`PortProbe`를 부르는 일이라 한 곳에 두는 게 맞고, D에 일이 몰려 있었다.
- **결정:** 원격 항목 주소는 `ppoling.yaml`에 적고 비밀값만 `.env`로 참조한다. `shell: true`는 지원하지 않는다. 지금 스키마·코드와 맞추기 위해.
- 기획서 v1.1: 발표자료의 Git 연동을 MVP에 다시 넣고(FR-19, AT-23·24) 기능 동결 일정 조정
- **결정:** Git은 브랜치·변경 표시와 전체 실행 전 pull(`--ff-only`, 실패하면 건너뛰고 실행 계속)만 MVP에 넣고 A가 맡는다. 브랜치 전환은 MVP 직후. 발표자료에서 MVP로 소개했는데 기획서에서 근거 없이 빠져 있었다.
- **결정:** 기능 동결을 4주차 금에서 5주차 수(12/2)로 미룬다. 구현 기간이 2주뿐이라 짧았다. 대신 테스트는 5주차 후반~6주차 전반으로 줄인다.
