# 송윤서 작업 기록

## 2026-11-18

**완료**
- 포트 확인(FR-06)의 포트 주인 찾기(`PortProbe.whoUses`)와 HTTP 확인(`HttpProbe`) 진짜 구현, `checks.register()`로 앱에 등록(Windows 약속 테스트 통과)

**결정**
- **결정:** 포트 주인은 OS 명령(Windows `netstat`·`tasklist`, macOS `lsof`)으로 찾고, OS별 코드는 `checks/lib/src/port_owner/`에만 둔다. `CLAUDE.md`가 `checks/`의 OS별 구현 파일을 허용해서.
- **결정:** macOS `lsof`가 못 찾으면 "비어 있음"이 아니라 "모름"으로 보고 포트를 직접 열어 확인한다. 관리자 권한 없이는 다른 계정 프로세스가 안 보여서.
- **결정:** Windows `netstat`은 상태 이름(`LISTENING`) 대신 상대 주소 포트가 0인 줄로 LISTEN을 판단한다. 상태 이름은 OS 언어마다 달라서.
- **결정:** `HttpProbe`는 리다이렉트를 따라가지 않고 본문은 읽고 버린다. 계약(3xx도 응답)과 맞추고, 큰 응답에 시간을 쓰지 않으려고.

**다음 할 일**
- 첫 조립(11/19)에서 A의 맥으로 `whoUses`(`lsof`)·Compose 확인, GUI 앱의 `docker` 경로 확인
- 포트 충돌 표시: `RuntimeQuery`와 합쳐 내 항목이면 [이동]·[그 항목 중지], 외부 프로그램이면 경고만(`PortNotice`)
- 원격 연결(FR-18) 화면 표시, 환경 점검(FR-07) `EnvChecker` 진짜 구현

## 2026-11-16

**완료**
- Docker Compose 제어(FR-08)·원격 연결 확인용 `ItemLauncher` 진짜 구현(`compose/` `DockerItemLauncher`), 실제 Docker로 약속 테스트 통과(Windows)
- `PortProbe.connect`(TCP 연결 확인) 진짜 구현(`checks/` `SystemPortProbe`). `whoUses`는 OS별 코드 위치를 정한 뒤 채움

**결정**
- **결정:** Compose 항목을 멈출 때 `down` 대신 그 항목 서비스만 `rm --stop --force` 하고, 프로젝트에 컨테이너가 하나도 안 남았을 때만 볼륨 없이 `down`으로 네트워크를 정리한다. 같은 프로젝트의 다른 항목을 건드리지 않으면서, 테스트로 확인한 네트워크 찌꺼기도 남기지 않으려고.
- **결정:** `DockerItemLauncher`는 `ProjectRepository`·`HttpProbe`·`PortProbe`를 함수로 받아 처음 쓸 때 꺼낸다. `register()` 안에서 바로 꺼내면 가짜가 진짜로 바뀌기 전일 수 있어서(`AppRegistry` 약속).
- **결정:** `SystemPortProbe`는 `whoUses`를 채우기 전까지 앱에 등록하지 않는다. 지금 등록하면 시작 전 포트 확인이 오류로 멈춰서.

**다음 할 일**
- macOS에서 확인, 앱을 아이콘으로 실행할 때 `docker`를 PATH에서 못 찾는 문제 확인
- A에게: `app/`에 `checks`·`compose` 연결, 앱에 `HttpProbe` 가짜 등록 요청
- `PortProbe` OS별 코드 위치를 팀에 확인한 뒤 포트 확인·소유 판별(FR-06) — 목요일 첫 조립에 붙이기
- 원격 연결(FR-18) 화면 표시, 환경 점검(FR-07)

## 2026-11-15

**완료**
- `ItemLauncher`(Compose·원격 항목) 계약과 상태 모델, 가짜 구현·약속 테스트 작성. A가 요청한 Compose 포트 주인 조회(`composeOwnerOf`) 포함
- `checks/`·`compose/` 패키지 골격 추가(`runner/` 본뜬 빈 `register()`)

**결정** (팀 리뷰 전 초안)
- **결정:** `ItemLauncher`는 준비 완료를 기다리지 않는다. 기다리기는 전체 실행(A)이 `status()`를 되풀이해 부르며 한다. 준비 조건 처리를 A 한 곳에 모으려고.
- **결정:** Compose 항목을 멈출 때는 그 항목의 컨테이너만 멈추고 지운다. 같은 compose 파일을 여러 항목이 나눠 쓸 수 있고, `down -v`처럼 볼륨을 지우면 데이터가 사라져서.
- **결정:** `composeOwnerOf`는 예외 없이 모르면 null을 돌려준다. A의 `RuntimeQuery` 약속(모르면 null)과 맞추려고.

- `PortProbe` OS별 코드 위치(`CLAUDE.md` "OS별 코드는 `runner/`에만")를 팀에 확인한 뒤 진짜 구현

## 2026-11-11

**완료**
- C 계약 초안 작성: `PortProbe`·`HttpProbe`·`EnvChecker` 계약과 결과 모델, `core/fakes` 가짜 구현, 약속 테스트

**결정** (팀 리뷰 전 초안)
- **결정:** 연결 실패·미설치 같은 점검 결과는 예외가 아니라 결과 값(`ProbeResult.ok`, `EnvStatus`)으로 돌려준다. 실패도 정상적인 답이고, QA·환경 점검 화면이 한 줄씩 그대로 보여줘야 해서. 예외는 포트 번호가 범위 밖일 때만.
- **결정:** `ProbeResult`의 칸(대상·응답 코드·응답 시간·실패 이유)을 `QaResult`와 맞춘다. D의 QA가 C 계약 결과를 그대로 옮겨 쓰게 하려고.
- **결정:** `PortProbe`는 포트를 쓰는 PID·프로그램 이름만 알려주고 종료하지 않는다. 내 항목인지는 A의 `RuntimeQuery`와 합쳐 판단한다. PID만으로 종료하면 남의 프로세스를 죽일 수 있어서.
- **결정:** 버전 조건은 `>=20`, `>=17 <22`처럼 공백으로 이은 비교식이고, 연산자 없는 `20`은 20.x 전부다.
