**결정**
- **결정:** AI 검사 화면에는 키 끝 4자리만 보이고, 8자 이하인 키는 모두 가린다. 짧은 키는 4자리만으로도 많이 드러나서.
- **결정:** 키를 저장하거나 지운 뒤에는 키 창이 돌려준 결과 대신 저장소를 다시 읽어 상태를 바꾼다. 목요일 조립 때 OS 보안 저장소에 실제로 들어갔는지 화면만 보고 알 수 있게.
- **결정:** 보안 저장소를 읽거나 쓰지 못하면 화면과 키 입력 창에 알리고, 창은 닫지 않고 다시 누를 수 있게 둔다. 그대로 두면 창이 "저장 중"으로 멈춰 있어서.
- **결정:** [연결 확인]은 키로 모델 정보만 물어보고(내용 없는 GET) 키는 저장하지 않는다. 결과는 AI 오류 안내 4종 문구를 그대로 쓴다. 사용자가 [보내기]를 누르기 전에는 내용을 보내지 않는다는 규칙을 지키려고.
- **결정:** 키 만드는 주소는 글로 보여 주고 복사하게 한다. 브라우저를 여는 `url_launcher`를 이것 하나 때문에 추가하지 않으려고.

**결정**
- **결정:** 카드의 실행 정보는 `catalog/` 안의 `RunInfoSource`로 받고, 그 구현이 A의 `Orchestrator`(마지막 전체 실행·항목 상태)를 읽는다. 화면이 실행 기록 계약 모양에 바로 묶이지 않게 하려고.
- **결정:** "실행 중 n/m"과 실행 중 개수에서 원격 항목은 세지 않는다. 원격 항목은 전체 종료 뒤에도 "연결됨"으로 남아, 세면 멈춘 프로젝트가 실행 중으로 보여서.
- **결정:** 카드의 [전체 실행]이 실패하면 카드에 한 줄 요약을 남기고 [열기]를 [대시보드에서 보기]로 바꾼다. 대시보드로 자동으로 넘기지는 않는다. 여러 프로젝트를 차례로 켜는 중에 화면이 넘어가면 불편해서.
- **결정:** 오래됨은 성공·실패와 상관없이 마지막 전체 실행일로부터 90일이 지난 것. 카드의 [열기]·[실행 방법 설정하기]는 프로젝트 ID를 넘기고, [프로젝트 추가]는 `/add-project`로 간다.
- **결정:** Gemini는 무료 등급으로 쓰고, 사용자마다(팀원 포함) 자기 키를 넣는다. 무료 사용량이 Google 프로젝트 단위라 키 하나를 나눠 쓰면 서로의 사용량을 깎고, 키를 주고받는 과정에서 새기 쉬워서.
- **결정:** API 키는 `flutter_secure_storage`로 OS 보안 저장소에 둔다. macOS는 로그인 키체인을 쓴다. 디스크에 평문으로 두지 않고, OS별 코드를 직접 쓰지 않으려고. 그리고 macOS 키체인 공유는 서명이 필요해서.
- **결정:** 모델은 `gemini-flash-latest`로 하고, 붐비거나 30초 안에 답이 없으면 `gemini-flash-lite-latest`로 한 번만 더 보낸다. `gemini-2.5-flash`가 새 사용자에게 막혀 있었고, 무료 등급은 붐빌 때가 잦아서.
- **결정:** API 키 앞글자(`AIza`)로 형식을 검사하지 않는다. 실제로 받은 키가 `AQ.`로 시작해서.

**결정** (팀 리뷰 전 초안)

- **결정:** 계약 함수는 실패하면 `PpolingException` 계열 예외를 던지고, 메시지는 화면에 그대로 보여줄 수 있는 문장으로 쓴다. 설정 검사(`ConfigValidator`)만 문제 목록을 돌려준다. 고칠 곳을 한 번에 모두 보여주려고.
- **결정:** 형식 검사(필수값·타입·이름 오타·경로)는 `ppoling.yaml`을 읽을 때, 항목끼리의 관계(중복 id·없는 의존 대상·순환 의존)는 `ConfigValidator`가 맡는다. FR-02를 두 단계로 나눠 각각 따로 테스트하려고.
- **결정:** `cwd`·`envFile`·compose `file`은 프로젝트 폴더 안 상대 경로만, `command`는 목록만 받는다. 작업 폴더·셸 해석 금지 규칙을 설정 파일 단계에서 먼저 막으려고.
- **결정:** `shell: true`, 키체인 비밀값, QA "전체 실행 후 자동"은 v1에서 뺀다. 아직 팀 결정 전이라, 정해지면 추가만 하면 되게.
