# 화면 리디자인 v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱 화면을 리디자인 목업 v2(기획서 v1.4 §9)대로 바꾼다 — 왼쪽 메뉴 틀, 개발 홈, 탭이 있는 프로젝트 화면, AI 분석 기록, 확인 창.

**Architecture:** `core`에 탭 등록(`AppRegistry.tab`)과 패널 자리(`ProjectPanels`)를 추가만 한다. `AppPage`를 왼쪽 메뉴 틀로 바꿔 모든 화면이 따라오게 하고, `runner`의 프로젝트 화면이 머리·실행 흐름·로그 탭을 그린 뒤 각 기능이 등록한 탭을 이어 붙인다.

**Tech Stack:** Flutter 데스크톱(Dart), 기능 폴더별 패키지(`popoling_<폴더>`), `flutter_test`.

**Spec:** `docs/superpowers/specs/2026-11-26-redesign-v2-design.md`

## Global Constraints

- 기능 폴더는 `core/`만 import한다(CI 검사). 다른 기능의 위젯은 `app/`이 조립해 `provide`로 넘긴다.
- `core/` 기존 인터페이스·필드는 고치지 않고 추가만 한다.
- 동작이 없는 버튼은 만들지 않고 숨긴다. 새 동작(상태 나누기, 시작 취소, 설치, Git 그래프, 최신 코드 받기)은 넣지 않는다.
- 상태는 색과 글자 라벨을 함께 쓴다. `.env` 값은 화면에 평문으로 내지 않는다.
- 화면 문구는 간결한 존댓말, 목업 문구를 그대로 쓴다(예: `실패 · 눌러서 원인 보기`, `오래됨 · 8개월`).
- 색·글자는 `core/lib/ui/theme.dart`의 `C`를 쓴다. 새 색만 추가한다.
- OS 분기는 화면에 두지 않는다.
- 목업 HTML(배치 참고): 아티팩트 `project/v2_*.dc.html` — 읽어서 배치만 참고한다.
- 테스트는 test-runner 에이전트로 패키지별 `flutter test`, 정적 분석은 `flutter analyze`.

## Review Focus

1. 설정 파일이 없거나(`config == null`) 실행 항목이 0개인 프로젝트 → 프로젝트 화면·홈·설정 탭이 깨지지 않고 "실행 항목이 아직 없어요" 류 안내를 보여야 한다. (Task 4, 7에 테스트)
2. 아주 긴 프로젝트 이름(`2025-2학기-캡스톤-동아리-행사-예약-웹서비스-최종-진짜최종`) → 메뉴·카드·머리에서 넘치지 않고 말줄임. (Task 2, 8에 테스트)
3. 계약 구현이 예외를 던짐(`EnvChecker`·`QaRunner`·`EnvDiff` 실패) → 탭이 빈 화면이나 빨간 오류 화면이 아니라 "확인하지 못했어요" 문구. (Task 5, 6에 테스트)
4. AI 기록 파일이 깨졌거나 없음 → AI 검사 화면이 빈 목록으로 열리고 파일을 덮어써 잃지 않는다(깨진 파일은 고치지 않고 안내). (Task 9에 테스트)
5. 좁은 창(최소 1024px 폭) → 실행 흐름 카드가 줄바꿈되고 가로 넘침이 없다. (Task 4에 테스트)
