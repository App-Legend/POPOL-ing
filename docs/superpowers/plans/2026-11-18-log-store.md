# 로그 저장(LogStore) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 포폴링이 띄운 프로세스 항목의 출력을 비밀값을 가린 채 회전 파일에 남긴다.

**Architecture:** `runner/` 안에 `LogStore`(파일 쓰기·가리기·회전)를 새로 두고, `RunnerOrchestrator._upProcess` 가 출력을 구독하는 그 자리에서 준비 확인과 `LogStore` 양쪽에 흘린다. 로그 폴더는 `runner.register` 에서 `path_provider` 로 구해 넘긴다.

**Tech Stack:** Dart/Flutter, `dart:io` `IOSink`, `path_provider ^2.1.5`

**Spec:** `docs/superpowers/specs/2026-11-18-log-store-design.md`

## Global Constraints

- 파일: `<앱 데이터>/logs/<프로젝트ID>/<항목ID>.log`, 회전 `.log.1`·`.log.2` — 10MB(`10 * 1024 * 1024` 바이트) 넘으면 밀어내고 3개까지.
- 실행마다 구분 줄: `--- 시작 <ISO 시각> ---`
- 줄 형식: `<ISO 시각> out | <내용>` / `<ISO 시각> err | <내용>` (시각은 `DateTime.toIso8601String()`).
- 가리기: 그 항목 `.env` 값 중 비어 있지 않은 것 → `****`. 쓰기 **전에** 가린다. `service.env`(popoling.yaml 값)는 가리지 않는다.
- 쓰기 실패는 실행을 막지 않는다(예외를 밖으로 내지 않는다).
- Compose·원격 항목 로그는 저장하지 않는다.
- 코드 주석·테스트 이름은 한국어, 주변 코드 문체를 따른다. OS 분기를 넣지 않는다.

## Review Focus

1. 빈 `.env` 값(`KEY=`) — `replaceAll('', …)` 이 글자마다 `****` 를 끼우면 안 된다. 빈 값은 무시. → Task 1 테스트
2. 한 비밀값이 다른 값을 포함(`abc`, `abcdef`) — 긴 값부터 가려야 `****def` 처럼 일부가 새지 않는다. → Task 1 테스트
3. 한글 등 여러 바이트 글자 — 크기는 글자 수가 아니라 UTF-8 바이트로 센다. 이전 앱 실행에서 남은 파일 크기도 처음부터 센다. → Task 1 테스트
4. 같은 항목을 다시 시작해 이전 출력이 아직 쓰이는 중 — 두 기록이 한 파일을 동시에 열어 회전이 꼬이거나 줄이 사라지면 안 된다. 항목마다 쓰기를 차례로 줄 세운다. → Task 1 테스트
5. 로그 폴더를 만들 수 없음(쓰기 금지 경로) — `record` 는 예외 없이 끝나고 항목 시작은 성공한다. → Task 1·2 테스트

### Task 1: `LogStore`

**Files:**
- Create: `runner/lib/src/log/log_store.dart`
- Test: `runner/test/log_store_test.dart`

**Interfaces:**
- Consumes: `OutputLine`(`runner/lib/src/process/process_launcher.dart`), `ItemRef`(`package:popoling_core/contracts.dart`)
- Produces:
  ```dart
  class LogStore {
    LogStore(Future<Directory> Function() root, {int maxBytes = 10 * 1024 * 1024, int keep = 3});
    /// [lines] 를 끝날 때까지 [item] 의 로그 파일에 쓴다. [secrets] 는 쓰기 전에 `****` 로 가린다.
    /// 같은 항목의 이전 기록이 남아 있으면 그게 끝난 뒤 쓴다. 쓰기에 실패해도 예외를 내지 않는다.
    Future<void> record(ItemRef item, Stream<OutputLine> lines, {Iterable<String> secrets = const []});
    /// [item] 의 지금 로그 파일(없을 수도 있다). FR-09 [파일 열기]·`LogExcerpt` 가 쓴다.
    Future<File> fileOf(ItemRef item);
  }
  ```
  `keep` 은 `.log` 를 포함한 파일 수(3이면 `.log`·`.log.1`·`.log.2`).

- [ ] **Step 1: 실패하는 테스트 작성** — 임시 폴더를 `root` 로 주고 `Stream.fromIterable([...OutputLine])` 을 넘긴다. 테스트:
  - `줄마다 시각과 out/err 를 붙이고 실행마다 구분 줄을 넣는다` — 두 번 `record` 후 파일 줄이 정규식 `^--- 시작 \S+ ---$`, `^\S+ out \| hello$`, `^\S+ err \| boom$` 순서이고 구분 줄이 2개.
  - `.env 값은 가리고, 빈 값은 무시하고, 긴 값부터 가린다` — secrets `['', 'abc', 'abcdef']`, 줄 `x=abcdef y=abc` → 파일에 `x=**** y=****`, `abc` 없음, 줄 길이가 망가지지 않음(`****h****e…` 아님).
  - `10MB 를 넘으면 밀어내고 3개까지 남긴다` — `maxBytes: 100`, 한 줄 ~40바이트 × 20줄 → `.log`·`.log.1`·`.log.2` 존재, `.log.3` 없음, 마지막 줄은 `.log` 에, 각 파일 크기 ≤ 100 + 한 줄 길이.
  - `크기는 UTF-8 바이트로 세고 남아 있던 파일 크기부터 센다` — `maxBytes: 100`, 미리 90바이트 파일을 써 두고 `'가나다라'`(12바이트) 한 줄 기록 → 회전되어 `.log.1` 이 생긴다.
  - `같은 항목 기록 두 개가 겹쳐도 줄이 섞이거나 사라지지 않는다` — `StreamController` 두 개로 `record` 두 번(첫 스트림을 아직 닫지 않음), 둘째에 줄 추가 후 첫째 닫고 둘째 닫기 → 첫째 줄들이 모두 둘째 줄들 앞, 줄 수 합이 맞다.
  - `폴더를 만들 수 없어도 예외 없이 끝난다` — `root` 를 일반 파일 경로 아래(`<임시파일>/logs`)로 → `await store.record(...)` 가 정상 완료.

- [ ] **Step 2: 실패 확인** — `cd runner && flutter test test/log_store_test.dart` → `log_store.dart` 없음으로 FAIL.

- [ ] **Step 3: 구현** — 항목마다 이전 `record` 의 Future 에 이어 붙여(`Map<ItemRef, Future<void>>`) 차례로 쓴다. `IOSink`(`FileMode.append`)에 쓰고, 바이트 수는 처음 `length()` + `utf8.encode(line).length + 1` 로 센다. 넘으면 싱크를 닫고 `.log.(keep-2)` → … → `.log` 를 한 칸씩 `rename`(가장 오래된 것은 덮어쓴다) 후 다시 연다. 가리기는 빈 값을 빼고 길이 내림차순으로 `replaceAll`. 전체를 `try`/`on FileSystemException`(그리고 싱크 오류) 로 감싸 삼키되, 입력 스트림은 끝까지 소비한다(안 그러면 보내는 쪽이 막힌다).

- [ ] **Step 4: 통과 확인** — 같은 명령 → PASS.

- [ ] **Step 5: 커밋** — `git add runner/lib/src/log runner/test/log_store_test.dart && git commit -m "feat(runner): 로그를 회전 파일에 저장하는 LogStore"`

### Task 2: 오케스트레이터·`register` 연결

**Interfaces:**

- [ ] **Step 1: 실패하는 테스트 작성** — 테스트 도우미 `orchestrator(...)` 에 `LogStore? logs` 인자를 더하고 기본값은 `tempProject()` 와 같은 방식의 임시 폴더 `LogStore`. 새 테스트(프로세스 그룹 안):
  - `실행한 항목의 출력을 .env 값을 가려 로그 파일에 남긴다` — `.env` 에 `SECRET=hunter2`, 명령 `echo "pw=$SECRET"; echo oops >&2; echo Started; exec sleep 30`, `LogReady('Started')`. 시작 성공 → 멈춤 후 `await logs.fileOf(item)` 내용에 `out | pw=****`, `err | oops`, `out | Started` 가 있고 `hunter2` 는 없다.
  - `로그 폴더를 쓸 수 없어도 항목은 시작된다` — 쓰기 불가 `root` 의 `LogStore` → `start` 결과 `ItemOutcome.ok`.

- [ ] **Step 2: 실패 확인** — `cd runner && flutter test test/runner_orchestrator_test.dart` → `logs` 매개변수 없음으로 FAIL.

- [ ] **Step 3: 구현**
  - 생성자에 `required this.logs` (`final LogStore logs;`).
  - `_upProcess`: `.env` 에서 읽은 값만 따로 두었다가 `secrets` 로 넘긴다.
  - 출력 구독: 지금 `listen` 콜백에서 `lines` 에 넣는 것과 함께 `StreamController<OutputLine>` 에도 넣고 `onDone` 에서 둘 다 닫는다. 그 컨트롤러 스트림으로 `unawaited(logs.record(item, ..., secrets: ...))`. 구독과 `readiness.wait` 사이에 `await` 를 두지 않는 기존 규칙을 지킨다.
  - 맨 위 `shortcut:` 주석에서 로그 부분을 빼고 실행 기록만 남긴다.
  - `runner.dart`: `logs: LogStore(() async => Directory('${(await getApplicationSupportDirectory()).path}${Platform.pathSeparator}logs'))`. 3주차 주석에서 `LogExcerpt` 는 그대로 둔다.
  - `cd runner && flutter pub get`
