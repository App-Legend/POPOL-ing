# 앱 화면을 리디자인 목업 v2로 바꾸기 — 설계

- 날짜: 2026-11-26
- 브랜치: `feat/redesign-v2` (기획서 v1.4 수정 `docs/plan-v1.4` 위에서 시작)
- 기준: `docs/포폴링_개발기획서.md` v1.4 §9, 리디자인 목업 v2(2026-11-23, 송윤서, claude.ai 아티팩트 "포폴링 데스크톱 UI" 2쪽)

## 1. 왜 하나

기획서 v1.4에서 화면 구성을 목업 v2 기준으로 바꿨다. 지금 앱은 v1.3의 화면 8개(대시보드·항목 상세·환경 점검·QA·설정이 각각 다른 화면, 위쪽 막대 하나)를 따른다. 사용자는 한 프로젝트를 보려고 화면을 여러 번 오가야 한다. v2는 왼쪽 메뉴 틀 안에서 프로젝트 화면 하나에 탭으로 모은다. 발표(12/17) 전에 앱이 기획서·목업과 같은 모습이어야 한다.

## 2. 목표 / 하지 않는 것 / 실패로 보는 것

**목표**
- 앱 전체 화면 배치를 목업 v2에 맞춘다: 왼쪽 메뉴 틀, 개발 홈, 프로젝트 화면(머리·알림 줄·실행 흐름·탭), AI 검사, 확인 창.
- 각 기능 폴더가 자기 화면(탭)의 주인인 구조를 지킨다. 화면은 `register()`로 끼운다.

**하지 않는 것 (v1.4의 새 동작은 역할분담대로 따로)**
- 상태 나누기(`시작 실패`·`준비 시간 초과`·`멈춤`·`대기 중`·`건너뜀`), [시작 취소]·[더 기다리기]
- 도구 설치·버전 바꾸기·`.env` 예시 복사(FR-07 확장)
- Git 브랜치 그래프·CI·PR 합치기(FR-20), [최신 코드 받기]
- 실패 안내 카드의 원인별 내용(D)
- 카테고리 선택 화면(`/`) 변경 — 그대로 둔다
- 왼쪽 메뉴의 [앱 설정] 화면 — 아직 화면이 없다(아래 6번)

**실패로 보는 것 (돌아가도 안 되는 것)**
- 동작이 없는 버튼을 보여 주는 것. 눌러도 아무 일 없는 버튼은 만들지 않고 숨긴다.
- 실행·종료·복구 동작이 바뀌는 것. 화면만 바꾼다(예외: 앱 종료 창 버튼 수, 7번).
- 상태를 색으로만 구분하는 것. 글자 라벨을 함께 쓴다.
- `.env` 값이 화면에 평문으로 나오는 것.

## 3. 지켜야 할 조건

- 기능 폴더는 `core/`만 import한다(CI가 검사). 다른 기능 폴더의 위젯을 직접 쓰지 않는다. 필요한 위젯은 `app/`이 조립하거나 등록으로 받는다.
- `core/` 1.0 이후 규칙: 기존 인터페이스를 고치지 않고 추가만 한다.
- OS 분기는 `runner/`·`checks/`의 OS별 파일에만 둔다. 화면에는 두지 않는다.
- 노신용 님 열린 PR #76·#77·#78(설정 화면·`ProjectHeader`)과 충돌한다. 사용자 결정: 지금 시작하고 충돌은 나중에 정리한다.
- B·C·D 폴더를 고친다. 사용자가 "앱 전체 한 번에"를 골랐다. PR 본문에 각 담당자 확인 요청을 적는다.

## 4. 고른 방법

| 방법 | 내용 | 장단점 |
|---|---|---|
| **① 공통 틀 + 탭 등록 (선택)** | `core/ui`에 왼쪽 메뉴 틀, `AppRegistry`에 탭 등록 추가. 프로젝트 화면(`runner`)이 머리·실행 흐름·로그 탭을 그리고 등록된 탭을 이어 붙인다 | 지금 `register()` 구조를 넓힐 뿐이라 각자 자기 탭만 고치면 된다. 계약을 하나 추가해야 한다 |
| ② `app/`에 프로젝트 화면을 통째로 | 모든 탭을 `app/`에서 그리고 기능 폴더는 데이터만 | 빠르지만 "화면도 기능 폴더가 맡는다"는 규칙이 깨진다 |
| ③ 화면은 그대로, 모양만 | 화면마다 메뉴를 씌우고 탭처럼 보이는 버튼으로 이동 | 코드가 가장 적지만 v1.4의 "한 화면 안의 탭"과 다르다 |

사용자가 ①을 골랐다. 이유: 이미 있는 `register()` 방식을 넓히는 것이라 이후 각자 자기 탭만 고칠 수 있다.

## 5. 설계

### 5.1 탭 등록 계약 (`core/contracts`, 추가만)

`AppRegistry`에 메서드 하나를 더한다.

```dart
/// 프로젝트 화면에 탭을 끼운다. 같은 id면 나중 것이 이긴다(가짜 → 진짜 교체와 같은 규칙).
void tab(ProjectTab tab);
```

`ProjectTab`(새 모델, `core/models` 또는 `core/contracts`): `id`, `label`(예: `환경 점검`), `order`(작을수록 앞), `build(BuildContext, String projectId) → Widget`, 선택 `badge(String projectId) → Stream<int>`(문제 수, 0이면 숨김).

- 구현: `app/lib/registry.dart`의 `Registry`가 탭을 모아 `order`순 목록으로 내준다. 프로젝트 화면은 `AppRegistry`를 받지 않으므로, `runner.register()`가 `/dashboard`를 만들 때 탭 목록을 넘긴다(읽기는 화면을 그릴 때).
- `AppRegistry`를 구현하는 테스트용 클래스 2개(`catalog/test/catalog_register_test.dart`, `ai/test/ai_register_test.dart`)에 `tab()`을 더한다.
### 5.1b 패널 자리 (`core/contracts`, 추가만) — 만드는 사람 결정

`runner`는 `ai`를 import할 수 없어서 로그 탭 안의 실패 안내 자리·[AI 요약] 자리를 `tab()`만으로는 채울 수 없다. `AppRegistry`는 더 고치지 않고, `core`에 패널 부품 형식을 하나 추가해 기존 `provide<>`로 넘긴다.

```dart
/// 프로젝트 화면 안의 끼울 자리. app/이 다른 기능의 위젯으로 채워 provide 한다. 없으면 자리를 숨긴다.
class ProjectPanels {
  final Widget Function(BuildContext, ItemResult item, RunSummary run)? failure; // 실패 안내 자리 (D의 FailureAnalysisPanel이 이 둘을 받는다)
  final Widget Function(BuildContext, QaRun run)? qaSummary;    // 헬스체크 [AI 요약] (D의 QaSummaryPanel)
}
```

지금 `app/lib/ai_slots.dart`의 `qaSummarySlot`이 하는 일을 이 형식으로 옮긴다. `runner`는 그릴 때 `read<ProjectPanels>()`로 꺼낸다(등록이 없으면 빈 값).

- 탭 순서(목업): 로그(0, runner 기본) · 환경 점검(10, checks) · Git(20, runner) · 설정(30, project). "시스템 아키텍처(이후)" 탭은 만들지 않는다.

### 5.2 왼쪽 메뉴 틀 (`core/ui`)

- `AppPage`(모든 내부 화면이 씀)를 왼쪽 메뉴 + 본문 틀로 바꾼다. 쓰는 쪽 코드는 그대로 두고 틀만 바뀌게 한다. `crumbs`는 본문 맨 위 작은 경로("내 프로젝트 / my-team-project")로 계속 쓴다.
- 메뉴 내용: 로고·`포폴링`, `카테고리 · 개발`(누르면 `/`), 내 프로젝트(`/home`), AI 검사(`/ai`), 앱 설정(화면이 없어 숨김), 아래쪽 "지금 상태".
- "지금 상태" 목록(실패한 프로젝트 "실패 · 눌러서 원인 보기", 오래된 프로젝트 "오래됨 · 8개월")은 `catalog`가 아는 정보다. `core/ui`는 기능을 import할 수 없으므로, 틀은 목록을 위젯으로 받는 자리만 두고(`InheritedWidget` 등) `app/`이 `MaterialApp.builder`에서 `catalog`가 내보낸 위젯을 넣는다. 구체 방식은 만드는 사람이 정한다.
- 카테고리 선택 화면(`/`)은 메뉴 없이 지금처럼 둔다.
- 색·글자 크기는 `core/ui/theme.dart`의 값(이미 시안 값)을 쓴다. 목업에서 새로 필요한 색만 추가한다.

### 5.3 프로젝트 화면 (`runner/`, A) — 지금의 `/dashboard`

목업 3·3b·3d·S1~S3 화면 기준.

- **머리**: 이름 + 프로젝트 요약 상태(지금 있는 상태로 `실행 중 · n/m`·`시작 중`·`일부 실패`·`중지` 계산), 스택 태그, 한 줄 설명·저장소 링크·메모 수(`about`), Git 뒤처짐 "최신 코드가 있어요 · 3커밋"(지금 `_gitLine` 정보), 요약 문장, [전체 실행]/[전체 종료]. 실행 중이 아니면 "어제 18:40에 마지막으로 실행했고 성공했어요"처럼 마지막 결과를 보여 준다.
- **알림 줄**: 지금 있는 알림만 옮긴다 — 설정 파일 문제(`configIssues`), 포트 충돌(지금 대시보드의 포트 안내와 [그 항목 중지]), pull 건너뜀·대기 안내. 새 실패 원인 문구는 만들지 않는다.
- **실행 흐름**: 항목 카드를 의존 순서대로 가로로 놓는다(이름, 종류·포트, 지금 상태 문구, 원격은 [다시 확인]). 카드를 누르면 로그 탭이 그 항목 로그로 바뀐다. 지금 항목 행에 있는 시작·중지 버튼은 카드에 둔다.
- **로그 탭**: 고른 항목의 실시간 로그(지금 `LogPreview`·`log_tab`·`detail_screen`의 로그 기능: stdout/stderr, 검색, 자동 스크롤, 복사, 파일 열기). 실패한 항목이면 로그 위에 실패 안내 자리를 두고 D의 `FailureAnalysisPanel`을 끼운다(아래 5.6). 그 아래 헬스체크 영역(5.4).
- **마지막 전체 실행 요약**(지금 `_summary` 패널): 목업에 따로 없다. 머리 요약 문장과 흐름 카드 상태로 대신하고 패널은 없앤다.
- `/detail` 화면은 없앤다. 항목 설정 보기는 설정 탭으로 간다.
- **Git 탭**(runner, order 20): 지금 머리에 있는 브랜치·변경 수·뒤처짐을 "원격과 비교" 카드로 보여 준다. [최신 코드 받기]·그래프는 넣지 않는다(새 동작).

### 5.4 헬스체크 영역 (`qa`, C)

- 진짜 `QaRunner`가 아직 없다(`FakeQaRunner`뿐, `qa/` 폴더 없음, 계약 주석상 담당 D). **사용자 결정: 가짜 결과를 보여 주되 "샘플 데이터" 표시를 분명히 한다.** 영역 제목 옆에 "샘플 · 진짜 검사 기능이 아직 없어요" 같은 라벨을 두고, 진짜 `QaRunner`가 등록되면 라벨이 사라진다(가짜인지는 등록된 구현이 `FakeQaRunner`인지로 판단하거나 `app/`이 알려 준다. 방식은 만드는 사람이 정한다).
- 지금 `app/lib/screens/qa_screen.dart`의 내용을 목업 3번의 헬스체크 표(결과·검사·응답·걸린 시간, [다시 검사], 요약 배지)로 바꿔 `QaRunner` 계약으로 그린다. 위치는 로그 탭 아래. `runner`가 계약만으로 그린다.
- [AI 요약]은 `ProjectPanels.qaSummary`(D의 `QaSummaryPanel`)를 끼운다. 샘플일 때도 누를 수 있지만 보내기 전 확인 창에 샘플이라고 보인다(지금 동작 그대로). [검사할 주소 추가]는 설정 편집이 생기기 전까지 숨긴다.

### 5.5 환경 점검 탭 (`checks/`, C, order 10)

목업 4번 기준. 지금 `app/lib/screens/env_check_screen.dart`(목업)를 없애고 `checks.register()`가 탭을 등록한다.

- **포트** 표: 포트·쓰는 항목·지금 쓰는 곳·상태(`PortProbe`, `RuntimeQuery`). 동작 버튼은 지금 있는 [그 항목 중지]만.
- **버전 확인** 표: 도구·필요 버전·이 컴퓨터·결과·설치 위치(`EnvChecker`). [설치하기]·[버전 바꾸기]는 넣지 않는다.
- **마지막 성공 때와 달라진 것**(`EnvDiff`): 항목·지금·마지막 성공 때·메모. 되돌리는 방법 버튼은 넣지 않고 글로만 안내한다.
- 탭 배지 = 문제 수(버전 불일치·포트 충돌·달라진 것).

### 5.6 설정 탭 (`project/`, B, order 30)

목업 6번·S4 기준. 지금 `app/lib/screens/settings_screen.dart`를 `project/`로 옮겨 탭으로 등록한다.

- 지금 `settings_screen.dart`는 값이 고정된 목업이고, 실제 저장(`updateProject` → `popoling.yaml`)은 열린 PR #76에만 있다. **사용자 결정: 읽기 전용.** 진짜 `ProjectRepository`의 설정을 목업 모양으로 보여 주기만 하고 편집 칸·[저장]은 숨긴다. #76이 합쳐진 뒤 B가 편집을 연결한다.
- 보여 줄 것: 소개·메모, 실행 항목 표(이름·종류·명령·포트·시작 순서)와 항목을 누르면 펼쳐지는 상세(명령 인자, 실행할 폴더, 먼저 시작할 항목, 포트, 준비 조건·최대 시간, 고급: `.env` 파일 이름·중지 대기 시간), 필요한 도구(`requires`) 표, 설정 파일 경로와 [파일 열기](OS 기본 프로그램으로 열기, 동작 있음).
- 설정 검증 문제(`configIssues`)가 있으면 해당 칸 옆에 보여 준다.
- PR #76~78과 겹치는 부분은 나중에 합친다.

### 5.7 개발 홈 (`catalog/`, D) — `/home`

목업 2·2a 기준.

- 제목 "내 프로젝트"와 개수, 안내 문구, [프로젝트 추가].
- 검색(이름·설명·기술), 필터(전체·실행 중·오래됨), 정렬(최근 실행순 등, 지금 있는 정렬).
- 카드: 이름·상태 라벨·한 줄 설명(없으면 "설명이 아직 없어요…")·스택 태그·마지막 실행·결과, 실패면 이유 한 줄. 버튼은 [열기]와 상태별 하나: [전체 실행]/[전체 종료]/[원인 보기](실패 → 프로젝트 화면)/[실행 점검](오래됨, FR-17이 있을 때). 실행 방법이 없으면 "실행 방법 없음".
- 묶음(팀·개인·회사)·단축키 표시는 하지 않는다(MVP 이후).
- 프로젝트가 0개면 2a 화면: "첫 프로젝트를 등록해 주세요", [프로젝트 폴더 고르기], 확인 안내 문구.

### 5.8 AI 검사 (`ai/`, D) — `/ai`

목업 7번 기준. 키 상태(끝 4자리)·[키 바꾸기], 안내 문구, 분석 기록 목록(종류·프로젝트·한 줄 결과·시각·받음/보내지 못함, 펼치면 원인·해 볼 것·근거·[다시 분석]/[다시 보내기]).

- **사용자 결정: 기록 저장까지 만든다.** 지금은 결과를 저장하지 않는다. `ai/`에 분석 기록 저장소를 새로 만든다. 저장 위치는 앱 데이터 폴더(기획서 §7: "AI 분석 기록(보낸 내용 요약·결과·근거·사용 모델·시각)"), 저장 내용도 그 목록대로. 비밀값·API 키는 저장하지 않는다(보낸 내용은 이미 가린 요약만). 실패한 전송("보내지 못함")도 이유와 함께 남겨 [다시 보내기]가 가능하게 한다.
- 원인 분석(AI-02)·AI 요약(AI-03)이 결과를 받거나 실패할 때 이 저장소에 쓴다. 로그 탭·헬스체크에서 받은 결과도 여기 남는다.
- 기록 개수 상한·오래된 기록 정리, 파일 형식은 만드는 사람이 정한다(파일 하나에 JSON, 최근 100개 정도가 기본안).
- `/ai`는 메뉴에서 `projectId` 없이 열린다(전체 기록). 대시보드에서 `projectId`와 함께 여는 버튼은 없앤다(원인 분석은 로그 탭으로 옮김).

### 5.9 확인 창

- 있는 창의 문구·버튼을 목업에 맞춘다: AI 키 입력(D4), 보내기 전 확인(D2), 앱 종료(D3), 다른 프로젝트 항목 중지(3c), 목록에서 빼기(D7, 있으면).
- 앱 종료 창(`runner/lib/src/screens/exit_guard.dart`)은 v1.4 FR-12대로 [취소]·[모두 종료하고 닫기] 두 개로 줄이고, 프로젝트별 실행 중 항목 이름을 보여 준다. [그대로 두고 닫기] 코드 경로는 지운다.
- 처음 실행 명령 확인(D1)은 PR #78에 있어 이번에는 손대지 않는다.

### 5.10 정리

- `app/lib/screens/`의 목업 화면 중 탭·새 화면으로 옮긴 것(`dashboard`·`detail`·`env_check`·`qa`·`settings`)과 주소 `/detail`·`/env`·`/qa`·`/settings`를 지운다. `_registerMockups`와 이 화면들을 여는 버튼도 함께 고친다.
- `/dialogs` 목업 화면은 개발용이면 남기고, 아니면 지운다(만드는 사람이 확인).

## 6. 만드는 사람이 정할 것

- `ProjectTab`을 `core/models`에 둘지 `core/contracts`에 둘지, `badge`의 정확한 모양
- "지금 상태" 목록을 메뉴에 넣는 방식(5.2)
- 헬스체크 위젯을 둘 패키지(5.4)
- 화면 크기별 배치(좁은 창에서 흐름 카드 줄바꿈 등), 목업 픽셀 값을 얼마나 맞출지. 목업 HTML은 아티팩트 `project/v2_*.dc.html`에 있다
- [앱 설정] 메뉴는 화면이 없어 숨긴다(API 키 바꾸기는 AI 검사 화면에 있다)

## 6b. 검토 뒤 정한 것 (2026-11-27)

- 사용자: 설정 탭 읽기 전용, 헬스체크는 "샘플" 표시하고 보여 줌, AI 분석 기록 저장까지.
- Claude(만드는 사람 판단): AI 패널은 `AppRegistry`를 더 고치지 않고 `core`의 `ProjectPanels` 형식 + `provide<>`로 넘긴다(5.1b).

## 7. 확인 방법

- `flutter analyze`, 패키지별 `flutter test`(test-runner 에이전트). 옛 화면 문구·주소를 찾는 테스트는 새 화면에 맞게 고친다.
- macOS 실제 앱에서 화면마다(홈·빈 홈·프로젝트 실행 중·일부 실패·환경 점검·Git·설정·AI 검사·종료 창) 스크린샷을 찍어 목업과 비교한다.
- import 규칙 CI 검사가 통과해야 한다.

## 8. 순서

1. 탭 계약·패널 자리 + 왼쪽 메뉴 틀(`core`, `app/registry`, `app/ai_slots` 정리)
2. 프로젝트 화면(`runner`): 머리·알림 줄·실행 흐름·로그 탭·Git 탭, `/detail` 정리
3. 탭 채우기: 환경 점검(`checks`), 설정(`project`), 헬스체크
4. 개발 홈(`catalog`)
5. AI 검사(`ai`): 분석 기록 저장소 + 화면
6. 확인 창, 앱 종료 창 두 버튼
7. `app/` 목업 화면 정리

단계마다 커밋한다.
