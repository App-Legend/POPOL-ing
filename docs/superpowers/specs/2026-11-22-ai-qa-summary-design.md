# AI-03 QA 결과 요약 설계

- 날짜: 2026-11-22
- 담당: D(`ai/`). 쓰는 계약: `QaRunner`(C, 지금은 가짜), `Orchestrator`(A), `LlmClient`(D)
- 브랜치: `feat/ai-qa-summary`
- 기준: 기획서 §2 "기본 QA와의 연계 (AI-03)", AT-20·21, 화면 문구 초안 §4·§5
- 이름: 화면에는 "헬스체크 결과 요약"으로 쓴다(우리 기획서에서 기본 QA = 헬스체크, 화면 문구 초안 §9 제안). 화면 6 제목은 C·팀이 정한다

## 목적

QA 결과가 길면 무엇이 문제인지 바로 안 보인다. [AI 요약]을 누르면 Gemini가 두세 문장으로 정리하고, 문장마다 근거(검사 항목·값·시각)를 붙인다. 통과·실패 판정은 규칙(FR-10) 그대로이고 AI는 설명만 붙인다.

## 목표 · 하지 않는 것

- 목표
  - 이번 검사 결과, 같은 항목의 최근 이력(최대 5회), 마지막 전체 실행 요약을 보내 2~3문장 요약을 받는다.
  - 문장마다 근거가 붙는다. 실패·느려진 항목 목록을 함께 보여준다.
  - 모두 통과하고 이전과 차이가 없으면 API를 부르지 않고 "모든 검사를 통과했어요"만 보여준다(AT-20).
  - [보내기]를 누르기 전에는 요청 0건. 보낸 내용에 호스트·`.env` 값·API 키가 없다(AT-21).
- 하지 않는 것
  - 분석 기록 저장(화면 8 분석 기록, #43, 4주차 후반)
  - 화면 6(QA 결과, C)에 끼우기. 위젯만 내보내 두고, 연결 방식은 C·A와 따로 정한다
  - `core/` 변경. `LlmClient.complete(prompt, system)` 그대로 쓴다
- 실패로 보는 것
  - AI가 판정을 바꾸는 것처럼 보이는 화면(예: 실패 항목을 "괜찮음"으로 표시)
  - 근거 칸에 실제 검사 결과와 다른 값이 나오는 것

## 방식 비교 (화면 6에 어떻게 붙일지)

| 방식 | 내용 | 장단점 |
|---|---|---|
| **1. 위젯으로 만들고 먼저 화면 8에 붙이기 (선택)** | `ai/`에서 `QaSummaryPanel`을 내보내고, 오늘은 D 화면인 `/ai`의 "헬스체크 결과 요약" 카드에 붙인다. 화면 6은 나중에 C 화면이 자리를 받고 `app/`(A)이 이 위젯을 넣는다 | 공통 코드를 건드리지 않는다. 화면 6 연결은 나중이다 |
| 2. `core`에 'AI 요약 자리' 계약 추가 | C 화면이 등록된 위젯을 꺼내 그린다 | 연결이 확실하지만 `core` 변경이라 팀 동의가 먼저다 |
| 3. 화면 6 버튼은 `/ai`로 이동만 | 요약은 화면 8에서만 보인다 | 가장 간단하지만 기획서의 "화면 6 아래에 결과"와 다르다 |

1번을 고른 이유: 기능 패키지끼리는 import할 수 없고(역할분담 §3), `core`를 바꾸지 않고도 지금 만들 수 있는 부분(로직·위젯)이 연결 방식과 상관없이 같다.

## 설계

### 1. 요약 로직 `ai/lib/src/qa_summary.dart` (화면 없음)

**보낼 글.** 검사마다 번호를 붙인다. 근거를 번호로 고르게 하려고.

```
[이번 검사] 2026-11-22 14:05 · 통과 1 · 실패 1 · 설정 필요 1
#1 API 헬스 · 실패 · GET /actuator/health · 503 · 120ms · 14:05:02
   최근: 통과 200 84ms (11/21 18:41), 통과 200 80ms (11/20 21:10)
#2 프론트 메인 · 통과 · GET / · 200 · 84ms · 14:05:02
#3 관리자 페이지 · 설정 필요(검사할 주소 없음)
[마지막 전체 실행] 11/22 14:00 · api 성공 · web 실패(준비 시간(60초)을 넘겼어요.) · db 건너뜀
```

- 주소는 호스트를 빼고 경로만 보낸다. `GET http://localhost:8080/actuator/health` → `GET /actuator/health`. 경로가 없으면 `/`.
- 포트 검사(`localhost:3306`)는 `포트 3306`만 보낸다.
- 최근 이력은 같은 이름의 항목을 이번 검사 앞의 이력에서 최대 5회까지 찾는다.
- 전체 실행 요약은 `Orchestrator.lastRun(projectId)`의 항목별 결과다. 없으면 그 줄을 뺀다.
- 실패 이유(`failureReason`)와 실행 실패 이유(`reason`)는 그대로 넣는다. 보내기 전에 `AiSender`가 비밀값을 한 번 더 가린다.

**API를 안 부르는 조건.** 아래를 모두 만족하면 고정 문구 "모든 검사를 통과했어요."만 보여준다.

- 이번 검사의 모든 항목이 통과(설정 필요가 하나라도 있으면 해당 안 됨)
- 직전 검사가 없거나, 직전 검사의 같은 이름 항목이 모두 통과
- 느려진 항목이 없음

**느려짐.** 그 항목의 이전 응답 시간 평균(최근 5회 중 응답 시간이 있는 것)보다 2배 이상이고, 차이가 200ms 이상이면 느려짐이다. 이전 기록이 없으면 판단하지 않는다.

**실패·느려진 항목 목록.** AI에게 맡기지 않고 앱이 계산한다. 실패, 느려짐, 설정 필요를 각각 라벨로 보여준다.

**AI에게 주는 지시(system).** 한국어, 터미널을 잘 모르는 사람도 알아들을 쉬운 말, 2~3문장. 판정을 바꾸거나 새 값을 지어내지 말 것. 답은 JSON 하나만:

```json
{"sentences": [{"text": "API 헬스가 503으로 실패했어요.", "checks": [1]}]}
```

**답 읽기.**

- ```` ```json ```` 울타리가 있으면 벗기고 첫 `{`부터 마지막 `}`까지 읽는다.
- `checks`의 번호가 이번 검사에 없는 문장, `checks`가 빈 문장은 뺀다. 완료 기준이 "문장마다 근거"라서.
- 남는 문장이 없거나 JSON이 아니면 "AI 답을 읽지 못했어요" 상태로 보여주고 [다시 요약]을 준다.
- 근거 칸은 앱이 실제 데이터로 만든다: `{이름} · {값} · {시각 HH:mm}`. 값은 응답 코드 → 실패 이유 → 응답 시간(ms) → 상태 라벨 순으로 있는 것 하나.

### 2. 요약 패널 위젯 `ai/lib/src/qa_summary_panel.dart`

`QaSummaryPanel(projectId, run, ...)`. `ai.dart`에서 내보낸다. 필요한 것(`LlmClient`, `ApiKeyStore`, `QaRunner`, `Orchestrator`)은 생성자로 받는다.

| 상태 | 보이는 것 (화면 문구 초안) |
|---|---|
| 처음 | "검사 결과를 AI가 두세 문장으로 정리해요. 누를 때만 분석하고, 보내기 전에 보낼 내용을 먼저 보여 드려요." · [AI 요약] |
| 키 없음 | "API 키 필요" 안내 · [키 입력] (AT-19) |
| 모두 통과, 이전과 같음 | "모든 검사를 통과했어요." (요청 0건) |
| 분석 중 | "분석하고 있어요. 그동안에도 실행·종료 같은 다른 기능은 그대로 쓸 수 있어요." · [취소] |
| 완료 | 문장마다 "근거  API 헬스 · 503 · 14:02", 실패·느려진 항목 목록, "요약 완료 · {모델 이름}", 판정 안내, [다시 요약] |
| 오류 | `llmErrorText` 4종(키 없음·키 오류·사용량 초과·네트워크)과 그 버튼 |
| 답을 못 읽음 | "AI 답을 읽지 못했어요." · [다시 요약] |
| 취소함 | "분석을 멈췄어요." · [AI 요약] |

- 보내기는 `AiSender.send(requestName: '헬스체크 결과 요약', notes: ['주소는 호스트를 빼고 경로만 보내요. 응답 본문은 보내지 않아요.'])`로만 한다.
- [취소]를 누르면 화면을 "취소함"으로 바꾸고 나중에 온 답은 버린다. 이미 보낸 요청은 Google 쪽에서 끝까지 처리될 수 있다.
- 상태는 색만으로 나누지 않고 글 라벨을 함께 쓴다.

### 3. 화면 8 카드 (`ai/lib/src/ai_screen.dart`)

- `/ai`로 넘어온 프로젝트 ID(`arguments`, 대시보드가 넘긴다)로 `QaRunner.history`의 첫 번째(가장 최근) 검사를 읽어 "헬스체크 결과 요약" 카드에 `QaSummaryPanel`을 그린다. 카드 머리에 "{오늘 14:05} 검사 기준".
- 검사 결과가 없으면 "아직 헬스체크 결과가 없어요."와 [헬스체크]를 보여준다. [헬스체크]는 누를 때만 `QaRunner.runChecks(trigger: manual)`를 부른다.
- 프로젝트 ID 없이 열리면 카드를 그리지 않고 지금처럼 "준비 중" 안내만 둔다.

## 시험

- 로직: 호스트 빼기(http·https·포트·경로 없음), 최근 5회만, 느려짐 경계값(2배·200ms), 안 부르는 조건(직전 실패 → 부름, 설정 필요 → 부름), 답 읽기(울타리, 틀린 번호 빼기, JSON 아님).
- 위젯: [보내기] 전 요청 0건·취소하면 0건(AT-21), 모두 통과면 확인 창 없이 고정 문구와 요청 0건(AT-20), 실패 판정 라벨이 요약 뒤에도 그대로, 근거 칸이 실제 값, 오류 4종, 취소 뒤 늦은 답 무시.
- 보낸 내용에 `localhost`·`http`·API 키가 없음.
- 가짜: `FakeQaRunner`, `FakeLlmClient`, `FakeOrchestrator`, `MemoryApiKeyStore`.
