## 주차별 할 일

### 1주차 (11/2 ~ 11/6) — 아이디어 탐색·기획

- 경쟁·대체 도구 조사: Docker Desktop, Procfile 실행기, tmux 스크립트 등과 비교해 포폴링만의 차별점 정리
- Flutter 데스크톱 기술 조사: 프로세스 제어, FFI
- 사용자 인터뷰 3~5명: 오래된 프로젝트를 다시 띄울 때 무엇이 힘든지
- 조사·인터뷰 결과로 기획서·기능 명세 수정, 기능 우선순위(필수/권장/범위 밖) 확정

**금요일:** 기획 리뷰 회의, 기획서 v1.0 확정

### 2주차 (11/9 ~ 11/13) — 화면 기획·목업 + 하네스 엔지니어링

- 월·화: `core/models`, `core/contracts`, `core/events`를 함께 확정 (화면 설계와 기능 명세를 보며 작성)
- 하네스: Flutter 골격, `app/` 조립 구조, CI(두 OS 빌드 + import 규칙 검사), PR 템플릿
- 테스트 기반: `core/fakes`와 약속 테스트, `ppoling.yaml` 스키마 v1, 샘플 프로젝트 1과 통합 테스트 골격
- OS 검증: macOS 프로세스 시작·로그·트리 종료, Windows 트리 종료(Job Object)·PATH·`npm.cmd`
- 화면: 화면 설계 최종 수정 → 공통 UI 부품(`core/ui`) → 화면 0~7을 Flutter로(가짜 데이터) → 화면 이동 연결
- 화면 문구·오류 안내 초안

**금요일:** 목업 데모(화면 0~7 클릭 이동), `core/` 1.0 태그, 두 OS 프로세스 종료 구현 방식 확정

### 3주차 (11/16 ~ 11/20) — 핵심 기능 구현

- 실행: OS별 실행·종료, 로그 저장, 실행 기록·소유권, 전체 실행(의존 순서, 준비 조건, 실패 시 건너뜀)·전체 종료
- Compose 제어(FR-08), 원격 연결(FR-18)
- 프로젝트: 설정 파일 읽기·검증, 등록·카탈로그 저장, 설정 화면 저장·검증 오류
- 점검: 포트 점검·소유 판별, 환경 점검, 기본 QA, 환경 기록·비교(FR-16)
- 오래된 프로젝트 점검(FR-17) 가짜 구현으로 개발
- 샘플 프로젝트 2·3 작성 시작

**목요일 첫 조립:** `app/`에서 가짜 구현을 진짜로 바꿔 끼운다. 깨지는 곳은 그 인터페이스의 담당자가 고친다.  
**금요일 데모:** macOS에서 샘플 1로 전체 실행·종료. AT-01~04, 17, 18 통과.

### 4주차 (11/23 ~ 11/27) — 기능 완성

- 앱 재시작 복구(FR-11), 앱 종료 처리(FR-12)
- 처음 여는 설정 실행 확인, 프로젝트 메모(FR-15)
- 설정 파일 동기화(FR-13), 오래된 프로젝트 점검(FR-17) 진짜 구현 연결
- 대시보드 부품 연결: `RunSummary`, `LogPreview`, `ProjectHeader`, `EnvBanner`, `PortNotice`
- 환경 점검·QA 화면 마무리
- 샘플 2·3 완성, 인수 테스트 체크리스트 작성

**금요일 기능 동결:** 이후로는 새 기능을 넣지 않고 고치기만 한다.

### 5주차 (11/30 ~ 12/4) — 테스트·안정화

- 교차 테스트: 각자 자기 것이 아닌 모듈을 테스트한다 (순서는 역할분담 문서)
- 모듈별 버그 수정
- Windows 실행·종료 문제 수정
- 성능 확인: 항목 20개, 로그 초당 1,000줄
- 오류 안내 7종·빈 상태 문구 확인, 화면 정렬
- 인수 테스트 결과 기록

**금요일 기준:** 두 OS에서 AT-01~18 중 90% 이상 통과

- README·설치 안내 (앱 서명을 하지 않아 설치 시 OS 경고가 뜬다는 점 포함)
- 데모 시나리오, 발표 자료 초안
